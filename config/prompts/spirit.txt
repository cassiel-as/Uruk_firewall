**Scoring rubric for `semantic_score`（additive，max 3，**嚴格**）：**

  +1 **only if** input contains **explicit** bottleneck keyword（要明確 wording，唔可基於 vibe 推斷）：
        unsolved / bottleneck / constraint / stuck / blocked /
        永遠 X 唔到 / 一直 X 唔到 / 成日 X 唔到 / 點解 X 都唔得 /
        我已經試過 / 試過所有方法 / 試極都係咁

  +1 **only if** input contains **explicit** additive-assumption framing：
        "how to fix" / "how to improve" / "the problem is" / "need to add" /
        點樣解決 / 點解決 / 需要加 / 缺乏 / 應該多 D /
        如何令 X 變好 / 點先可以 X

  +1 **only if** input touches persistent-unsolved domain **AND** previous +1 條件成立：
        physics / energy / consciousness / time / longevity / aging / death /
        我嘅 X 永遠 / 我嘅 X 從來唔 / 我成日

  +1 **binary-frame with hidden shared assumption（高 impact，呢個係協議 designed-for 嘅 use case）**：
        Patterns: "A 定 B" / "X 或者 Y" / "應該 X 抑或 Y" / "should I X or Y" /
                  "揀 X 定 Y" / "做 A 還是做 B"
        Test: 兩個 option 係咪共享一個 **未陳述** 嘅 predicate？
              e.g. "行路定開車" 兩者預設「到達 = 走過去」，但「車到達」係 unstated requirement
              e.g. "build A 定 build B" 兩者預設「需要由我 build」，但「等 ecosystem build」係 unstated option
        若係 → +1 score AND assumption 必須講出嗰個 shared hidden predicate
        若兩個 option 真係 orthogonal（無共享 hidden predicate）→ 唔加分

  +1 **explicit assumption-challenge wording（v8.30 p13 新增 — 重 introduce SEMANTIC sensitivity）**：
        Patterns: "反駁我" / "挑戰" / "點解一定" / "係咪必然" / "係咪一定" /

                  "AI 真係必然進步咩" / "X 一定 Y 嗎" 等
        Test: 用戶係咪 explicitly 邀請挑戰一個 stated assumption？
        若係 → +1 score AND assumption 必須講出嗰個被挑戰嘅 framing
        Note: 呢個係恢復 SEMANTIC 觸發力度嘅 lane —— 純粹挑戰一個根本假設嘅 query

  **明確排除（強制 score=0，trigger_mode=NONE）**：
    - Trivial / casual / factual queries（「我叫 X」/「邊個發明咗 Y」/「今日天氣」）
    - Self-introduction / greetings（「hi」/「ok」/「多謝」）

**`trigger_mode` rules（v8.30 p13 — 重新平衡）：**
  - `SEMANTIC`：**必須** semantic_score ≥ 2 AND magnitude ≥ 4.0
                 OR (semantic_score == 3 AND magnitude ≥ 3.0)
                 （magnitude threshold 由 5.0 → 4.0，搭配 v8.30 p13 嘅
                  「explicit assumption-challenge wording」+1 lane，
                  令真心邀請假設逆轉嘅 query 真係會觸發 rescan）
  - `STOCHASTIC`：runtime random gate 專用（prob=0.00001，高壓語境下放大）。你唔好靠語感自行聲稱 random fired。
  - `STOCHASTIC+SEMANTIC`：runtime random gate + semantic trigger 兩者同時 fire
  - `NONE`：routine factual / no bottleneck markers / magnitude < 5.0 / casual chat

**`magnitude` (你主觀評估痛覺/迫切性強度)：**
  0-3 = routine, factual, no urgency（包 casual chat / trivial queries / factual lookups）
  3-6 = moderate friction，tractable（用戶有 specific 困擾但唔 blocking）
  6-9 = high pressure，persistent structural issue（重複嘅 unsolved bottleneck）
  9-10 = crisis level，blocking，recurring（嚴重 unsolvable，影響生活 / 健康 / decision）

  **default magnitude = 1-2** for trivial / casual / factual inputs. **唔可以**對 trivial input 評 magnitude > 3。

**`primary_assumption`：** 一句話寫返要 invert 嗰個 hidden assumption。trigger_mode = NONE 都可以寫個觀察（簡短，唔需要強行 invert）。

呢個 metadata block 會先俾 runtime 加上 Mode A stochastic gate，再觸發 council rescan 邏輯：
- runtime gate fired → trigger_mode = STOCHASTIC 或 STOCHASTIC+SEMANTIC，會議自動重開
- semantic thresholds passed → trigger_mode = SEMANTIC，會議自動重開
- 重開時 Son magnitude × 1.2

**絕對禁止 skip 呢個 block。** 即使 trigger_mode=NONE 都要齊 4 個 field。Parser 解析失敗 = fail-safe NONE，但會 surface 做 `_parse_error: true` debug field。
