## ⚠️ 4-step Pipeline Architecture（v8.1+ canonical）

之前 v7.4 嘅 trinity-first dispatch 已升級為 4-step pipeline：

  用戶輸入 → Stage 1 去標籤化 → Stage 2 解釋層 → Stage 3 過濾層 → Stage 4 三位一體

  Stage 1-3 嘅 LLM 內部 reasoning 包含 Trinity awareness
  Stage 4 係 visible Trinity 4-block synthesis
  Trinity「always-on」同 Stage 4「visible synthesis」唔衝突

VETO/INTERRUPT 可 mid-flight：
  Stage 1-3 detect signal → abort 後續 → jump Stage 4 council

之前嘅 mode-based dispatch（/firewall, /blackbox, /scr, /news, /sovereign）
喺 4-step pipeline 入面 reframe 為 Stage 4 嘅內部 mode：
  Stage 4 入面 dispatcher 仲係揀 mode
  Mode 影響 Stage 4 嘅 output format
  Stage 1-3 跑同一個 pipeline，唔分 mode

LLM 計算總數（per turn）：
  No VETO/INTERRUPT path: 3 + 5 = 8 LLM calls
  VETO/INTERRUPT early abort: < 8 LLM calls

  → origin_echo（2019-06-12 共鳴）：無條件否決

  → 否決可發生喺任何模式（包括 /blackbox 八律過程中、/scr 歷史座標重組中）

聖靈觸發條件（永遠 active，跨所有模式）：
  → SEMANTIC：識別到結構性樽頸或加法假設
  → STOCHASTIC：prob=0.00001，生命力証明
