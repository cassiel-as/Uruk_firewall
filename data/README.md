# data/

Local knowledge corpus, generated run records, RAG index, and self-upgrade artifacts.

## Canonical Knowledge Areas

| Path | Meaning |
|---|---|
| `core/` | Always-loaded anchors such as `KAIROS_CORE.md` and `PHYSICS_CONSTANTS.md`. |
| `theory/` | Coordinate theory, coordinate cards, civilization anchors, and related papers. |
| `misc/` | Supplementary theory evidence, data supplement, gap-resolution, and English physics support files. |
| `protocol/` | Canonical protocol documents: Trinity, delabeling, explanation layer, SCR, BrowserNode, Source Coordinate Registry. |
| `causal_db/` | CAU causal calibration database. |
| `causal_records/` | Longitudinal causal/news records used as calibration evidence. |
| `world/` | Curated real-world geo-temporal anchors: historical events with date, latitude/longitude, tags, and causal links for the World Geo Timeline. |
| `index/` | Human navigation and summary indexes. |
| `kairos/` | Causality memory: `KAIROS_ACTIVE.md`, archive index, query-only logs, and proposal queue. Not raw transcript storage. |
| `scr_profiles/`, `scr_examples/` | SCR profiles and examples. |
| `benchmarks/` | Deterministic benchmark cases for coordinate-card selection and output self-eval. |

## Generated / Runtime Areas

| Path | Meaning |
|---|---|
| `conversation_history/` | Saved markdown sessions. Generated by `save_kairos()`. |
| `harness_episodes/` | Machine-readable replay companions for sessions. |
| `index/EXPERIMENT_INDEX.md`, `index/HARNESS_EPISODE_INDEX.md`, `index/UPGRADE_HISTORY_INDEX.md` | Generated runtime summary indexes. These are the RAG-safe entry points for experiments, harness episodes, and self-upgrade history. |
| `rag_index/` | Generated TF-IDF RAG index. Rebuild after active knowledge changes. |
| `prompt_regression_baseline.json` | Baseline fingerprint for runtime prompt/protocol assets. |
| `audit_log/`, `upgrade_plans/`, `upgrade_reports/`, `tmp/` | Self-upgrade and runtime working data; reports are generated JSON + Markdown summaries. |
| `_conversation_history_trash/`, `_kairos_legacy_backup_*` | Historical backup material. Do not treat as active knowledge. |

## Knowledge Manifest

`data/knowledge_manifest.json` defines which files are active, canonical, and resolvable by namespace. The manifest is the control plane for:

- `--ref` resolution
- RAG health
- duplicate basename drift checks
- coordinate card health
- knowledge trace metadata in harness episodes

Adding a new canonical knowledge file usually means updating `knowledge_manifest.json` or placing the file under an existing manifest collection.
